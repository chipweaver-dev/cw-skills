# 工作流：从选题到交付

本文定义任务目录、17 个制作步骤、3 个正式 Gate 与内部检查点。所有路径相对**任务根**（`<task_root>`）。

## 1. 任务根与版本

### 1.1 目录骨架

```text
<task_root>/
├── pre-production/
│   ├── v0.1/
│   │   ├── pre-production.md      # 意图、脚本、分镜、视觉规范、素材清单
│   │   └── review.md              # Gate 1 评审记录
│   ├── v0.2/                      # 返工版本，不覆盖 v0.1
│   ├── research/                  # 事实表、来源、截图
│   ├── resource/                  # 原始素材：PDF、图片、录屏、品牌资产
│   └── review_log.md              # 全局评审日志
├── production/
│   └── v0.2/
│       ├── toolbox/               # 单功能脚本 + spec JSON + reading_text.json
│       ├── S1/                    # 每个叙事单元一个素材包
│       │   ├── assets/
│       │   ├── preview/
│       │   └── elements.json
│       ├── S2a/
│       └── run.bat                # Windows 入口；Linux 用 Makefile
├── post-production/
│   ├── timeline.json              # 唯一播出时钟
│   ├── subtitles.json             # 行级字幕 cue
│   ├── audio/film/                # narration, music bed, scored mix
│   ├── web/                       # Vite + React + TS 播放页
│   └── review.md                  # Gate 3 评审记录
├── .tmp/                          # 本地草稿、截图、日志；不交付
└── README.md                      # 当前状态、如何重建、交付入口
```

### 1.2 版本规则

- 前期与制作各自带版本：`pre-production/v0.2` 与 `production/v0.2` 可以不同步；但 `timeline_source.json` 必须注明它读的是哪个 pre-production 版本。
- 已批准版本只读。返工新建版本目录，把上一版复制过去再改；`review_log.md` 写清"为什么返工、改了哪些段"。
- `.tmp` 只放临时产物：CDP 截图、解码探针、试混、对比图。任何需要复现的文件必须移入正式目录。
- 输出文件不写绝对路径；脚本以 `--root <task_root>` 解析，便于整个任务搬移。

### 1.3 什么放进 toolbox

只放**可重复执行的单功能脚本**和它们的 JSON spec：

- 一个脚本只做一件事：抠图、合成一层、导出图层、生成时间轴、混音。
- 复杂流程用 `run.bat` / `Makefile` 组合，不写一个"大而全"的脚本。
- 脚本顶部集中放 ffmpeg 查找、字体、画布尺寸等环境常量；业务参数放 spec JSON。
- `toolbox/Readme.md` 逐脚本写：用途、输入、输出、示例命令、依赖。

## 2. P0 立项（开工前）

### 2.1 Brief 必含字段

缺任何一项都不要开始写脚本：

1. **受众**：先修知识假设；他们已知什么、不知道什么。
2. **平台与画幅**：B 站/YouTube 横屏 16:9，或抖音/Reels 竖屏 9:16；分辨率与安全区。
3. **总时长**：目标值 + 允许区间 + **逐段落时间预算表**；预算之和必须等于总时长。
4. **风格 playbook**：技术/器件/架构类默认 `minimalist-diagram`；需要真实历史素材才考虑 `documentary-montage`，并先确认素材可得。
5. **叙事单元模板**：每个单元必须填的固定字段（如年份、公司/型号、工艺、解决的问题、关键规格、典型应用）。
6. **素材清单与来源分级**：指定教材/主素材 > 标准组织与厂商官方资料 > 论文与机构档案。
7. **旁白与 TTS 配置**：语言、音色、语速、采样率、格式、情绪；偏离默认才写明。
8. **音乐要求**：是否需要、风格、是否允许合成、片尾处理。

### 2.2 输入审计

- 逐一核对 brief 引用的素材路径是否存在；PDF 页码、图表编号是否对得上。
- 原始素材放入 `pre-production/resource/`，只读；不要直接在 `input/` 上做处理。
- 需要联网补的年代/规格，先列检索清单，再开始写脚本。
- 记录**无法获得**的素材：它是换叙事单元、换表现方式，还是标 N/A？在 brief 里决定，不留到 assets 阶段。

### 2.3 立项风险表

在 `pre-production.md` 末尾维护一张小表：

| 风险 | 触发条件 | 影响 | 预案 |
|---|---|---|---|
| 某型号找不到合规图 | research 阶段无 Wikimedia/厂商图 | 该拍无法满足"具体型号必须配图" | 换型号或删该拍 |
| TTS 读错术语 | 试听样本 | 字幕/旁白不一致 | 读音层替读 |
| 时长超预算 | 实测语速高于假设 | 需删句或加段 | 先删重复论证，不加快语速 |
| 音乐授权不可用 | 素材站无授权/无 key | 无法交付 | 本地合成铺底 |

## 3. P1 前期（步骤 1–6，Gate 1）

组织方式：**按叙事单元写，全局规范最后写**。`pre-production.md` 的顺序：

```text
# 标题
## 章节 S1
### Segment Brief
### Outline
### Script
### Storyboard
### Style Guide
### Asset List
## 章节 S2a
...
## 全局信息
### Proposal / 受众 / 平台 / 技术栈 / 时间预算
### 视觉规范（色板、字体、卡片母版、深度指示器、顶部覆盖层、图像处理、动效、字幕）
### 术语模板 / 旁白与 TTS 契约 / 读音层
### 素材总表与来源分级 / 转场表 / 开放问题 / Gate 映射
```

每段先写"这段解决什么问题"，再写脚本；全局规范最后统一，避免每段各写一套色板。

### 3.1 步骤 1：选题（Topic Brief）

- 一句话承诺：观众看完能回答哪个问题？
- 反常识钩子：前 3 秒必须给出反常识断言或数字，不做"大家好，今天讲"式铺垫。
- 范围边界：明确不讲什么，防止脚本膨胀。
- 成功标准：可衡量（能复述因果链、能说出 3 个关键数字、能区分相邻层级）。

### 3.2 步骤 2：大纲（Content Outline）

- 全片是**因果链**，不是名词年表。每个单元回答：旧事物具体瓶颈是什么（可量化）→ 新事物用什么机制解决 → 留下什么新瓶颈。
- 相邻单元用"上一个留下的新瓶颈"衔接；写不出衔接就说明单元顺序有问题。
- 先定段落表：`段 ID / 标题 / 叙事任务 / 预算秒数 / 关键画面 / 衔接句`。
- 预算之和 = 总时长；每段至少留 10% 余量给 TTS 实测偏差。

### 3.3 步骤 3：脚本（Script）

- 旁白只讲因果与论点；数字交给画面。单屏最多 1 句论点 + 1 组规格/数据。
- 中文旁白按**实测语速**反写字数上限。默认先用 4.2 字/秒做预算，再用一条样本校准；不要沿用 3.2–3.6 的旧假设。
- 技术关键词首次出现用"中文（English）"，之后直接用英文；上屏与旁白用同一写法。
- 每个数字标注来源 ID；来源表在 `research/`。
- 每拍写：`beat id / 旁白 / 屏幕信息 / 预算 / 关键词 / 舞台绑定`。
- 章节卡与片尾卡是**只显示、不朗读**的静音段，脚本里单独标注，不计入旁白字数。

### 3.4 步骤 4：分镜（Storyboard & Shot List）

- 每拍至少写：画面主体、构图、元素进入顺序、镜头运动、转场、停留时间。
- 信息密集卡用分级揭示：0–2 s 身份信息与配图 → 2–5 s 核心数据 → 5–8 s 机制与结论；旁白断句与揭示点对齐。
- 具体型号/设备必须配真实图：芯片、模组、主板或整机照；不能只放抽象示意图或纯文字卡。
- 转场表单独列出：`Gate id / at / from / to / 目标 / 音效 / 时长`；转场点必须落在段边界。
- 竖屏分镜按安全区画：顶部平台 UI、底部字幕/按钮、右栏互动区都要避开。

### 3.5 步骤 5：视觉风格（Style Guide）

固定一套母版，全片复用：

- 色板：背景、面板、网格、细线、主文字、次文字、强调色、实测蓝、模型灰、蓝图色；给十六进制值。
- 字体：标题/正文/等宽/数字；字号阶梯；中英文回退；交付前确认授权。
- 卡片母版：字段顺序固定；代际切换时高亮变化字段、弱化未变化字段。
- 深度/年代指示器：横屏底部时间轴，竖屏顶部时间转盘或侧边时间轴；当前位置高亮，旋转始终向前。
- 顶部覆盖层：面包屑、关键词徽标、品牌标；给出 y 坐标与横向安全边距。
- 图像处理：统一圆角、裁切比例、低饱和调色；暗色厂商图用 gamma 提亮，不用 gain。
- 动效语言：进入/退出时长、缓动、交叉淡化；转场音效母题；克制使用。
- 字幕规范：字号、行高、最多两行、底部安全区、英文高亮色。

### 3.6 步骤 6：素材清单（Asset List）

每个素材一行，字段固定：

| ID | 类型 | 描述 | 用于拍 | 来源/作者 | 许可 | 处理方式 | 状态 |
|---|---|---|---|---|---|---|---|
| A01 | 实拍/厂商图 | 某型号芯片正面 | s2f-b1 | URL | CC BY-SA / 厂商授权 | 抠图+统一调色 | approved |
| A02 | 自绘 SVG | Bank/MAT 层级 | s2c-b3 | 本任务 | 自有 | 3x 超采样 | approved |
| A03 | 录屏 | 任务管理器 | s1-b1 | 自录 | 自有 | 裁切+高亮 | approved |

- 来源分级写在表头或脚注；找不到合规图的条目在 script 阶段就替换/删除，不带病进入 assets。
- 需要 AI 辅助的只限**非历史、非实物**的抽象纹理/背景；不得生成伪造照片、人物、产品。
- 素材清单要覆盖：实拍图、示意图、图表、图标、录屏、字体、音乐、音效。

### 3.7 Research 与事实表

`research/` 至少两份产物：

1. `sources.md`：编号、标题、出版者、年份、URL/页码、访问日期、可信度分级。
2. `facts.json` / `facts.csv`：每个叙事单元一行 × 固定字段；每个数字单元格附 `source_id`；查不到写 `"N/A"`。

规则：

- 模型记忆中的数字一律视为待核实；定量陈述必须逐条有来源。
- 教材未覆盖的年代必须联网检索一手来源（JEDEC、datasheet、发布稿、论文）。
- 人工核对事实表后才进入 script；script 只从表中引用数字。
- 上屏区分 `[实测]`（蓝）与 `[模型]`（灰）；`[实测]` 不进入页面角标，直接呈现；`[模型]` 保留角标。
- 片尾参考资料：编号 + 标题 + 出版者 + 年份 + URL/页码；竖屏短片只上屏 3–5 条核心来源，其余放描述区或 research 产物。

### 3.8 Gate 1：Pre-Production Review

审核对象：`pre-production/<version>/pre-production.md` + `research/` + `resource/` 清单。

通过条件（逐项勾选，见 `checklists.md` §2）：

- Brief 八项齐全；预算之和等于总时长。
- 因果链完整；每个瓶颈可量化；单元之间有衔接。
- 脚本每个数字有来源；字数按实测语速反写；钩子在前 3 秒。
- 分镜每拍可执行；具体型号有配图计划；转场落在段边界。
- 视觉规范可直接落地（色板、字体、卡片母版、安全区、字幕）。
- 素材清单覆盖全部拍；许可与来源明确；无法获得的条目已处理。

结果只有 `Approved` 或 `Revise`。`Revise` 必须写清阻塞项，不写"再优化一下"。

## 4. P2 制作（步骤 7–10，Gate 2）

### 4.1 步骤 7：素材生成（Raw / AI Assets）

按素材包组织，每包对应一个叙事单元：

```text
S2c/
├── assets/
│   ├── backgrounds/          # 可选；通常由页面画
│   ├── layers/*.png          # 透明底元素
│   └── marks/*_marks.png     # 红色标记/光晕，透明底
├── preview/
│   ├── stills/*.png          # 供评审的合成静帧（含页面覆盖层）
│   └── contact_sheet.png
└── elements.json             # 每拍引用了哪些图层、文字、矢量
```

- 真实图：先裁切到目标区域，再抠图/擦除；能裁切解决就不要 inpaint。保留原图与处理记录。
- 透明底：统一圆角、统一描边、统一调色；边缘去白边；暗图用 gamma。
- 示意图：SVG/CSS 绘制，不用 3D；导出 3 倍超采样 PNG 或直接由页面渲染 SVG。
- 每个元素有稳定 ID；`elements.json` 是页面唯一引用入口，不靠文件名猜。
- 预览静帧必须与页面合成结果一致；不一致时以页面为准修素材，不手改预览。

### 4.2 步骤 8：配音（Voice-Over）

- 整片一次 TTS 请求；返回音频 + 逐句 sentence frame。
- 读音层 `reading_text.json` 只改**送给引擎的文本**；上屏文本反向还原为原文。
- 每条旁白合成后做 EBU R128 两遍归一化：target −16 LUFS、TP −1.5 dBTP、LRA 11；真峰超标用 `--dynamic` 重跑。
- 由 sentence frame 推导拍边界：边界落在两句之间的静音；太窄的间隙取中点并标记。
- 章节卡在段界拼入静音（只显示、不朗读）；片尾卡在音轨结束后追加显示时间。
- 产出 `timeline.json` + `subtitles.json`，并保留 `narration.json`（逐句 frame）供复查。

### 4.3 步骤 9：音乐音效（Music & SFX）

- 每个视频必须有音乐方案；没有音乐必须取得用户**显式同意**。
- 优先免版权素材；若素材站无授权/无 key/下载失败，改用本地合成铺底（可复现、无授权风险）。
- 音乐低存在感：铺底约 −29 LUFS，旁白期间 ducking 6–10 dB；不得压过归一化旁白。
- 章节卡可用一个节奏/riser 母题；全片克制，不堆音效。
- 分轨保留：`music_bed.wav`、`film_full_norm.mp3`、`film_full_scored.mp3`；改音乐不重录旁白。

### 4.4 步骤 10：图形动画（Graphics & Animation）

- 播放页是最终渲染器：一个 1080×1920 舞台，等比缩放到视口；页面只读 `timeline.json`。
- 主时钟用 `requestAnimationFrame`；音频以主时钟为准，做单侧漂移校正（如 >250 ms 才 seek）。
- 透明图层 + 页面文字/面板/光晕；每拍自动量包围盒并平移到内容中心，限制在安全区内。
- 章节卡清屏，只留标题与品牌；片尾卡清屏，logo 从 0.58 倍放大到 1.0 后停住。
- 顶部覆盖层（面包屑/关键词/品牌）常驻，章节卡与片尾卡期间隐藏。
- 提供评审参数：`?record=1`、`?autoplay=1`、`?t=SEC`、`?badge=KEY`、`?safe=1`；键盘 Space/←/→/Home。

### 4.5 Gate 2：Production Review

审核对象：素材包、`timeline.json`、`subtitles.json`、播放页、音乐分轨。

通过条件（见 `checklists.md` §3–§5）：

- 每个型号/设备有合规配图；素材透明底、无覆盖层；contact sheet 与页面一致。
- 时间轴段/拍连续、无重叠；字幕逐句、不越段；章节卡与片尾卡窗口正确。
- 页面 `?t=` 定帧稳定；段边界音画同点；安全区内无遮挡。
- 旁白 −16 LUFS；音乐 ducking 可听但不抢；片尾收束自然。

## 5. P3 后期（步骤 11–17，Gate 3）

### 5.1 步骤 11：粗剪（Rough Cut）

- 在播放页里过全片，检查叙事节奏、段落时长、转场是否成立。
- 记录问题按三类：**结构**（删/换段）、**节奏**（拍长）、**细节**（字/色/位置）。结构问题先改，不先抠细节。

### 5.2 步骤 12：锁画（Picture Lock）

- 冻结 `timeline.json`；此后只允许字幕/混音/编码修改，不再改拍长与舞台绑定。
- 锁画时打 tag/版本号，复制一份 `timeline.lock.json` 到 `post-production/`。
- 锁画后任何画面改动都要新版本，不在锁画文件上热改。

### 5.3 步骤 13：调色（Graded Master）

- 跨来源图片统一：圆角、裁切比例、低饱和、统一黑位；形成"同一套图鉴"。
- 暗色厂商图用 gamma 提亮，避免 gain 把噪点拉起来。
- 页面底色、面板、文字对比度统一；红色强调只用于标记/关键词，不大面积铺。

### 5.4 步骤 14：混音（Mastered Audio）

- 旁白归一化到 −16 LUFS / TP ≤ −1.5 dBTP。
- 音乐铺底 −29 LUFS 左右；按旁白包络 ducking 6–10 dB（attack ~40 ms / release ~700 ms）。
- EQ：高通 32 Hz、低通 6500 Hz、3 kHz 附近 −3 dB，给旁白让路。
- 终混再归一化到 −16 LUFS；真峰超标先修，不靠限幅硬压。
- 片尾卡音乐继续并淡出；不要出现"旁白结束音乐突然断"。

### 5.5 步骤 15：字幕（Subtitles）

- 每条 cue 对应一个 TTS sentence frame；行级对齐，不做逐字高亮。
- 每条最多两行；英文技术词用全片强调色；数字与画面一致。
- 最后一句停在段末，不伸进下一张章节卡；章节卡/片尾卡期间不显示字幕。
- 竖屏字幕放底部安全区（如 y 1436–1540），避开平台按钮区。
- 交付 SRT/ASS 时保留时间码与换行；上屏文本用原文，不用读音层替读文本。

### 5.6 步骤 16：母版（Master File）

- 录屏播放页：1080×1920、30 fps、H.264 + AAC、目标平台兼容码率（如 10–12 Mbps）。
- 录屏前确认：`?record=1` 隐藏控制条、全屏、无鼠标、无通知、无浏览器 UI。
- 校验：时长、分辨率、帧率、音轨响度、首尾黑帧、章节卡/片尾卡完整。
- 同时导出封面帧（竖屏信息流可读）与字幕文件。

### 5.7 步骤 17：平台版本与元数据

- 平台版本：按需出 9:16 / 16:9 / 1:1；不直接裁切横屏构图，重新排版。
- 元数据：标题、简介、标签、章节时间点、参考资料、版权说明。
- 发布清单：封面、字幕、音乐署名（如需要）、素材许可、敏感信息检查。

### 5.8 Gate 3：Post-Production Review

审核对象：成片 MP4、封面、字幕、元数据、交付包。

通过条件（见 `checklists.md` §6–§7）：

- 全片看一遍：叙事完整、音画同步、字幕无错、无黑帧/静音异常。
- 响度实测达标；音乐不抢旁白；片尾收束完整。
- 安全区无遮挡；小屏可读；英文高亮正确。
- 素材许可与参考资料齐全；无凭证/隐私泄露；工程可重建。

## 6. 评审闭环

### 6.1 `review.md`

每个 Gate 一份，字段固定：

```markdown
# Review: <Gate / Step>

- Artifact: <路径或链接>
- Version: v1
- Reviewer: <人名 / agent>
- Date: 2026-10-17

## Acceptance Criteria
- [ ] 标准 1
- [ ] 标准 2

## Status
- [ ] Pending
- [ ] Approved
- [ ] Revise

## Feedback
- [阻塞] ...
- [非阻塞] ...

## Next Action
- Approved → 进入 <下一步>
- Revise → 修改 <产物> 后重新提交
```

### 6.2 `review_log.md`

```markdown
# Review Log

| Gate | Step | Version | Status | Reviewer | Date | Feedback |
|---|---|---|---|---|---|---|
| G1 | Script | v1 | Revise | ... | ... | 第 2 段瓶颈不够具体 |
| G1 | Script | v2 | Approved | ... | ... | — |
```

### 6.3 Decision log

对"用户裁定过、后续不能再争"的事项单独记 `decision_log.json` 或 `decisions.md`：

- 字幕行级 vs 逐字高亮；
- 某个术语的读法；
- 某段的取舍；
- 音乐风格/是否要音乐；
- 具体镜头的表现方式。

每条写：`id / date / decision / reason / scope`。后续评审引用决策 ID，不重复讨论。

### 6.4 高效评审方式

- 用 `?t=SEC` 定到关键帧截图，不用手动拖时间轴找。
- 用 contact sheet 一次看完整段素材，不逐张点开。
- 段边界、章节卡中点、片尾卡各取 2–3 帧，检查切换与停留。
- 音频问题用波形/响度数据定位，不靠"感觉有点小"。
- 反馈分**阻塞**（不修不能过 Gate）与**非阻塞**（可记录后后续处理），避免 Gate 无限延长。

## 7. 返工与失效传播

| 上游改动 | 必须重跑 | 可复用 |
|---|---|---|
| 改一句旁白 | 整片 TTS、归一化、边界、timeline、subtitles | 素材、页面、音乐结构 |
| 改段落顺序/增删段 | 整片 TTS、timeline、字幕、转场、音乐 riser | 单段素材（需重绑 ID） |
| 改视觉规范 | 页面样式、预览静帧、contact sheet | 旁白、时间轴 |
| 改素材坐标 | 该段图层导出、预览、`elements.json` | 旁白、音乐 |
| 改音乐 | 重混、终混归一化 | 旁白、时间轴、画面 |
| 改画幅/平台 | 重新排版、重新录屏、重出封面 | 旁白、素材（若比例兼容） |
| 改面包屑/关键词文案 | `timeline_source.json` → `timeline.json`/`subtitles.json`（复用缓存 mp3）、`scenes.json`、重录画面 | 旁白音频、混音 |

原则：**上游改动向下游传播，下游改动不逆流**。不要为了少重跑而在页面里写死补偿。

重跑任何会被渲染读取的数据之前，先停掉在跑的渲染任务；同时只允许一个渲染任务，否则旧任务最后写回母版（见 `pitfalls.md` 8.6）。

## 8. 排期参考（5 分钟竖屏，单人 + agent）

| 阶段 | 参考占比 | 主要工作 |
|---|---|---|
| P0 立项 | 5% | 确认 brief、素材审计、风险表 |
| P1 前期 | 25% | research、脚本、分镜、视觉规范、素材清单 |
| P2 制作 | 45% | 素材包、TTS/时间轴、页面、音乐 |
| P3 后期 | 20% | 评审、混音、字幕、录屏、编码 |
| 交付 | 5% | 封面、元数据、发布检查 |

时间主要花在**素材合规**与**评审返工**，不是脚本本身。前期把事实与素材定死，后期就不会反复。
