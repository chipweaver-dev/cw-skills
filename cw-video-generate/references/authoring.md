# 内容与视觉作者规范

本文回答"写什么、怎么写得可拍、画面上怎么排"。工程实现见 `pipeline.md`。

## 1. 旁白

### 1.1 旁白负责论证，画面负责数字

旁白只讲三件事：旧事物卡在哪、新事物用什么机制解决、这留下了什么新问题。规格、年份、速率、容量、位宽尽量交给画面上的规格卡/图表，旁白不逐项念数字。

反例：

> "它的容量是 4 GB，速率是 3200 MT/s，位宽是 64 位，电压是 1.2 V。"

正例：

> "容量涨上去之后，问题从'存不下'变成了'取不快'。瓶颈从阵列转移到了接口。"

画面上同时给出 `4 GB / 3200 MT/s / 64-bit / 1.2 V` 的规格卡。

### 1.2 单屏一条论点

一个镜头只承载一条论点 + 一组数据。出现第二个并列论点时，切镜头，不要在一屏堆两组数字。

检查方法：遮住旁白只听画面，能否用一句话说出这屏在讲什么？说不出来就是信息过载。

### 1.3 开头 3 秒

短视频（≤3 分钟）前 3 秒必须是反常识断言、具体数字或冲突，不做自我介绍、不铺垫时代背景。

可用钩子类型：

- 反常识："内存不是一块，而是一座八层地址城。"
- 数字："同一颗芯片，行激活一次要等 30 纳秒，而 CPU 一次访存只要 0.3 纳秒。"
- 冲突："容量翻了 64 倍，延迟却几乎没降。"

### 1.4 术语

- 首次出现：中文（English），例如"行缓冲（row buffer）"。
- 之后直接用 English 原词，不反复括注。
- 同一术语全片只保留一种写法；上屏、旁白、字幕、检索表一致。
- 缩写若 TTS 读错，用读音层替读，不改上屏文本（见 §1.6）。

### 1.5 字数预算

中文旁白按**实测语速**反写。默认 TTS 音色在 4.3–4.5 字/秒；预算阶段用 4.2 字/秒留余量。

```text
字数上限 ≈ 段落预算秒数 × 4.2
```

写完后用一条真实 TTS 样本校准；如果实测明显偏离，先改预算假设，再改脚本。不要先写满 3.6 字/秒的旧假设，合成后才发现每段都短一截。

### 1.6 读音层

只替换引擎会读错的词，不修改旁白语义：

- 全大写缩写被逐字母念：`DRAM → D ram`、`MUX → Multiplexer`。
- 多音字选错：`行地址 → 航地址`（只取音节，语义不参与合成）。
- 型号被拆成字符：`1Rx16 → 1 rank 乘 16`。

规则：

- 替换表写 `canonical / reading / expect_occurrences`；实际出现次数不符就报错退出，防止文本改动后静默失配。
- 上屏与字幕一律用 `canonical`，反向还原；不能用替读文本上屏。
- 替换会改变字符数，所以字幕必须按 sentence frame 对齐，不能按字符位对齐。
- 读音层是否正确只能靠人耳验收；TTS 的 word timestamp 不含音素信息。

## 2. 事实与来源

### 2.1 来源分级

1. 指定教材 / 主素材（最高）。
2. 标准组织与厂商官方资料：JEDEC、datasheet、产品发布稿、技术白皮书。
3. 论文、机构档案、博物馆馆藏。
4. 维基百科/百科类：只用于找线索，不作为最终数字来源。

教材未覆盖的年代必须联网检索一手来源；二手博客、AI 摘要、论坛回帖不算来源。

### 2.2 事实表

`research/facts.json` 每个叙事单元一行，字段固定，每格附来源：

```json
{
  "unit": "S2c",
  "year": {"value": "1998", "source": "S03"},
  "org": {"value": "JEDEC", "source": "S03"},
  "problem": {"value": "pin count vs bandwidth", "source": "S05"},
  "mechanism": {"value": "time-multiplexed command/address", "source": "S05"},
  "spec": {"value": "SDR 100 MHz, 64-bit", "source": "S07"},
  "status": "verified"
}
```

- 查不到：`{"value": "N/A", "source": "N/A"}`，不要用推测值或模糊范围。
- 人工核对后才进 script；script 只引用表中值。
- 上屏数字与表中值必须完全一致；改数字先改表。

### 2.3 标注

- `[实测]`：本次实测/官方 datasheet 明确值，用蓝色（示例 `#4EA0E4`）。
- `[模型]`：推算/建模/估算值，用灰色（示例 `#8B95A1`），必须保留角标。
- 不要把 `[实测]` 角标画进页面；实测值直接呈现，只有 `[模型]` 保留标记。

### 2.4 参考资料页

片尾列：编号 + 标题 + 出版者 + 年份 + URL/页码。每条停留可读。

- 横屏/长视频可滚动列出全部来源。
- 竖屏短片只上屏 3–5 条核心来源；其余放视频描述区或 `research/sources.md`。
- 不要用"图片来自网络"这种不可追溯的写法。

## 3. 结构

### 3.1 因果链模板

每个单元按同一顺序写：

1. **旧状态**：上一代/上一层的具体瓶颈，带数字。
2. **机制**：新事物用什么结构/协议/工艺解决。
3. **代价**：新方案引入什么新问题（面积、功耗、延迟、复杂度）。
4. **衔接**：这个新问题就是下一单元要解决的。

如果某单元写不出"代价"，它可能只是一个名词解释，应该合并或删除。

### 3.2 段落预算

- 先定总时长，再按叙事权重分配。
- 每个单元至少 20 秒，否则转场与字幕来不及建立。
- 章节卡 1.2–2.0 秒；片尾卡 2.5–4.0 秒；从预算中单独扣除。
- 预算表各段之和必须等于总时长，误差 0；用 `check_film.py` 或脚本校验。

### 3.3 转场

- 转场必须有语义：下钻、拉远、切面、时间跳转；不要为了动而动。
- 转场点落在段边界；一个转场只做一件事。
- 音效母题（如转盘 tick、低沉 whoosh）全片统一，克制使用；不要每个镜头都加。

## 4. 竖屏视觉系统

### 4.1 画布与安全区

以 1080×1920 为基准（页面内部坐标）：

| 区域 | y 范围 | 用途 |
|---|---|---|
| 平台顶部 UI | 0–150 | 不放置任何内容 |
| 顶部覆盖层 | 150–300 | 面包屑 y≈176、关键词徽标 y≈232、品牌标 y≈228 |
| 内容区 | 332–1410 | 主画面；目标中心 y≈900 |
| 字幕带 | 1434–1542 | 字幕，最多两行 |
| 平台底部 UI | 1560–1920 | 不放内容 |

横向：安全边距 120 px；抖音右栏互动区约 `x ≥ 930`，关键信息不要放进去。

横屏构图不能直接裁成竖屏；必须重新排版：规格卡纵向排列、示意图旋转/重排、字幕下移。

### 4.2 色板（起点，不是教条）

| 角色 | 示例值 |
|---|---|
| 背景 void | `#0C0F14` |
| 面板 panel | `#151A21` |
| 网格 grid | `#1E252E` |
| 细线 hairline | `#333D49` |
| 主文字 | `#E7E9EC` |
| 次文字 | `#9AA3AD` |
| 强调/朱红 | `#E14A2B` |
| 实测蓝 | `#4EA0E4` |
| 模型灰 | `#8B95A1` |
| 蓝图色 | `#5C7A99` |

规则：

- 一个画面最多一个强调色焦点；红色只给标记/关键词/关键数字，不大面积铺。
- 深底上的细线不要低于 `#333D49`，否则手机亮度下消失。
- 文字对比度按 WCAG AA 检查；次文字不要用在关键数字上。

### 4.3 字体与字号（起始阶梯）

| 角色 | 起始字号 |
|---|---|
| 章节标题 | 72–88 |
| 卡片主标题 | 48–60 |
| 正文/说明 | 30–36 |
| 数据/规格 | 40–56，等宽数字 |
| 面包屑/角标 | 22–26 |

- 中文用系统黑体（如 Microsoft YaHei / Noto Sans SC），英文用 Inter 或同类无衬线，数字用等宽。
- 交付前确认字体授权并自托管；开发期可用系统回退。
- 一屏最多 3 种字号层级。

### 4.4 卡片母版

全片同一母版，字段顺序固定：

```text
[身份]  年份 / 公司 / 型号
[问题]  上一代的具体瓶颈（数字）
[机制]  新结构/新协议（一句）
[规格]  2–4 个关键数字
[结论]  留下了什么新问题
```

代际切换时：变化字段高亮（强调色），未变化字段降到次文字色。不要整卡换色。

### 4.5 分级揭示

信息密集卡按三拍揭示：

- 0–2 s：身份信息 + 真实配图。
- 2–5 s：核心数据/规格。
- 5–8 s：机制示意 + 结论。

旁白断句与揭示点对齐；不要一开场就把所有字段铺满。每拍只增加一个视觉焦点。

### 4.6 深度/年代指示器

- 横屏：底部时间轴，当前段高亮，左右为前后时代。
- 竖屏：顶部时间转盘（圆环年份刻度 + 固定指针 + 当前区间高亮，旋转始终向前）；次选侧边竖向时间轴或顶部紧凑年份条。
- 指示器常驻可见，但不要压过内容；章节卡/片尾卡期间可隐藏。
- 转盘旋转方向始终向前，不能因为回溯而倒转。

### 4.7 顶部覆盖层

- 面包屑：显示当前层级路径（如 整机 → DIMM → Rank → Chip → Bank → MAT → Cell），当前位置高亮。
- 关键词徽标：当前术语 + 一句解释，跟随旁白切换。
- 品牌标：右上角，固定位置，不参与内容布局。
- 三者 y 坐标固定；素材中按旧版坐标排的元素，页面统一下移，不在每个素材里改。

## 5. 真实图片与示意图

### 5.1 真实图片

- 只在可溯源来源获取：Wikimedia Commons、厂商资料室、博物馆馆藏、标准组织公开资料。
- 记录 URL、作者、许可、访问日期；交付包保留。
- 芯片/模组/整机必须能认出型号；不要用"类似产品"的图冒充。
- 找不到合规图：换型号、换叙事单元或删除该拍；不要用 AI 生成图补位。

### 5.2 处理链

1. 裁切：按边缘能量/内容包围盒找到主体，去掉无关背景；能裁切解决就不做 inpaint。
2. 去背：抠图/擦除，输出透明 PNG；保留原始边缘，不要过度羽化。
3. 统一：圆角、描边、裁切比例、低饱和调色；跨来源图看起来像同一套图鉴。
4. 提亮：暗色厂商图用 gamma（如 1.2–1.6），不用 gain；gain 会放大噪点。
5. 超采样：矢量标记/细线按 3 倍尺寸绘制再缩小，避免锯齿。
6. 检查：透明角落、白边、半透明像素、缩放后的文字可读性。

### 5.3 示意图

- 结构、流程、层级、时序一律自绘（SVG/CSS/绘图脚本），不生成"历史照片"或伪造实物。
- 一张卡最多一个示意小图；复杂机制拆成多拍，不要在一张图里塞完。
- 示意图的标注文字由页面绘制，不烘焙进图片；这样改语言/字号不用重导。
- 图表用真实数据，标单位与来源；趋势图用对数轴时明确标注。

## 6. 动效

- 进入/退出用短时长：元素 200–320 ms，整拍交叉 240–280 ms。
- 缓动统一（如 easeOutCubic）；不要混用弹跳、回弹、线性。
- 元素按信息层级依次进入，不整屏同时淡入。
- 镜头运动只做一种：推、拉、平移、下钻；一个镜头不要同时推和转。
- 章节卡：清屏 → 标题/短线/品牌淡入 → 停留 → 淡出接回舞台。
- 片尾卡：清屏 → logo 从 0.58 倍放大到 1.0（约 1.2 s）→ 停住收片。
- 所有动效不得改变内容包围盒的测量结果（见 `pitfalls.md` 的测量章节）。

## 7. 字幕

- 一条 cue 对应一个 TTS sentence frame；整句行级高亮，不做逐字 karaoke。
- 最多两行；优先在标点/从句处断行，不把英文术语拆开。
- 英文技术词用全片强调色；数字与画面完全一致。
- 最后一句停在段末，不伸进下一张章节卡；章节卡/片尾卡不显示字幕。
- 字幕带 1434–1542；竖屏底部安全区，避开平台按钮。
- 上屏文本用 canonical 原文；读音层只影响引擎。

## 8. 音乐与音效

- 每个视频都要有音乐方案；没有音乐必须取得用户明确同意。
- 默认低存在感铺底：不抢旁白、不盖低频、不频繁转调。
- 旁白期间 ducking 6–10 dB；旁白停顿时缓慢恢复（release ~700 ms），不要抽气式抖动。
- 章节卡可用 riser/tick 母题；片尾用终止和弦收束，最后 2 s 淡出。
- 音乐来源必须可商用/免版权；保留授权说明。素材站不可用时本地合成，避免"先用了再说"。
- 音效只做单点强调，不堆叠；同一音效全片只用一种变体。

## 9. 以观众视角自检

交付前用手机看一遍，检查：

- 前 3 秒是否知道"这视频要讲什么"？
- 不看字幕能否听懂主线？看字幕是否跟得上？
- 每个数字是否能在画面上找到，且与旁白不冲突？
- 深色画面在户外亮度下是否还能看清细线和小字？
- 章节卡是否给了呼吸感，还是只是黑屏？
- 片尾是否收得住，还是音乐突然断？
- 看完能否复述"旧瓶颈 → 新机制 → 新瓶颈"的链条？

任何一项答不上来，回到对应阶段修改，不要在编码阶段用滤镜/音量补救。
