# cw-hdl-module-analyze：HDL Module 复现级设计文档生成

## 1. 目标与验收标准

将 RTL 源码转化为一份**复现级设计文档**：一名具备基础 RTL 设计能力、从未接触过该代码的工程师，仅凭此文档即可写出功能等价的模块。

三条硬指标（缺一不可）：

1. **完整性**：源码中所有对外契约——端口、参数、宏依赖、复位行为、接口时序、状态编码——均被记录；端口/参数覆盖率 100%（由 `scripts/validate_report.py` 强制校验）。
2. **精确性**：位宽给公式、状态给编码、行为给决策表或时序图(Waveform Json 文件)；事实性陈述中禁止"大致/大概/基本上"等措辞。
3. **可信性**：事实与推断分离，凡非直接读自源码的结论必须按 `references/analysis-guide.md §1` 的标注体系标记。

## 2. 适用 / 不适用

**适用**：单文件或少量文件中的可综合 RTL module（Verilog-2001 / SystemVerilog 子集）；用户给出源码（文件或代码块），需要理解、文档化、交接、复现。

**不适用**（明确告知用户改用专门工具/方法）：
- 语法 lint、CDC 正式检查、综合错误诊断 → Verilator/Spyglass 类工具
- 整代码库级分析 → 本 skill 面向"单模块 + 其直接子模块契约"粒度
- 验证代码分析 → UVM/testbench 只在 §11 复现指南中作为行为参考

## 3. 工作流程（五阶段）

### Phase 0 · 输入确认

- 多 module 文件：默认只详析用户指定的 module；未指定则先列出全部 module 供用户选择。
- 模块例化了工程内其他模块：默认只登记到 §5.2 子模块表（端口契约层面），不展开内部；用户要求深入时再补充源文件迭代分析。
- 检测到 `` `宏 `` 引用但拿不到 defines 文件：先向用户索要；索要不到，把受影响的声明列入报告 §10 未决项，**不得臆测宏值**。

### Phase 1 · 机械提取（脚本做机械活）

- `extract.json` 的 `parser_warnings` 是**必查清单**，逐条到源码人工核对，不是噪音。
- 脚本是"尽力而为"的启发式提取器；其输出是线索，不是结论。

### Phase 2 · 深度分析（Agent 做理解活）

开始前通读 `references/analysis-guide.md`，按顺序完成七个动作并形成草稿：

1. 时钟与复位架构（guide §2）
2. 端口分组与职责归纳（guide §3）
3. always 块逐块归纳（guide §4）
4. 状态机提取（guide §5）
5. 接口协议识别（guide §6）
6. 关键内部信号与寄存器清单
7. 位宽/参数公式整理（guide §7）

对期望质量拿不准时，对照 `references/example-analysis.md`。

### Phase 3 · 成文

- 复制 `references/report-template.md` 作为骨架；**章节编号 1–12 不可增删**（校验脚本依赖编号），标题文字可微调。
- 逐节填写，遵守各节 HTML 注释中的填写规则，交付前删除全部 HTML 注释。
- 所有源码引用格式为 `文件名:行号` 或 `文件名:起-止行`；无对应内容的章节写"不适用 + 一句依据"，禁止删除章节。

### Phase 4 · 校验

- 修复全部 ERROR；每条 WARN 给出处理说明（改报告或在 §10 登记）。
- 最后做"复现测试"自检：假想一位未见过源码的工程师按文档实现，实现所需信息（端口、参数、复位、状态编码、转移条件、协议时序）是否都能在文档中找到？找不到的回到 Phase 2 补齐。

## 4. 输出规范

- 默认输出 `<module_name>_design.md`，与源码同目录（或用户指定路径）；多 module 时每 module 一份。
- 语言与用户一致；位宽统一 `[MSB:LSB]` 记法；时间统一注明单位。
- 框图/时序图使用 ASCII art 放入代码块（保证纯文本可读），可另附 mermaid。
- 单处源码引用 ≤10 行，且必须紧跟意图解释。

## 5. 硬性红线（违反任何一条即返工）

1. 禁止臆造源码中不存在的信号、参数或行为；不确定就写"未能确定 + 缺什么信息"。
2. 端口表与参数表覆盖率必须 100%（Phase 4 脚本强制）。
3. 事实性陈述必须可回溯到源码行号。
4. 全文所有 `[ASSUMED]`/`[UNVERIFIED]` 必须在报告 §10 集中汇总。
5. 禁止以粘贴源码代替行为描述。

## 7. Skill 维护约定（面向维护者）

- **分层原则**：SKILL.md 只放流程与红线；填写规则在模板内；分析方法在 guide 内。改任何一层不牵连其他层。
- **新增分析维度**：guide 加方法节 → 模板加对应章节（编号顺延）→ `validate_report.py` 的 `REQUIRED` 同步追加 → 用一个真实模块全流程回归。
- **脚本升级**：保持 extract 的 JSON schema 向后兼容（只增字段不改语义）；解析不到一律走 `parser_warnings`，绝不静默丢弃。
