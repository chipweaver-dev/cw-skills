# 深度分析方法论（Phase 2 指南）

## §1 事实 / 推断 / 假设三级标注体系

| 标注 | 含义 | 生成规则 | 去向 |
|------|------|----------|------|
| （无） | 事实 | 直接读自源码，句末附（file:line） | 正文 |
| [INFERENCE] | 高置信推断 | 由命名/结构模式推出（如 *valid/*ready 的握手语义） | 正文，句末标注 |
| [ASSUMED] | 假设 | 输入缺失下的假设（宏值、外部模块行为） | 正文 + §10 汇总 |
| [UNVERIFIED] | 无法核实 | 需工具/仿真才能确认（latch、综合警告、关键路径） | 正文 + §10 汇总 |

示例：
- `baud_cnt` 为 15 位计数器，异步复位值 0（uart_tx.v:71）。 ← 事实
- i_data 需在 i_valid 高电平期间保持稳定 [INFERENCE]（无缓存寄存器，uart_tx.v:88）。
- CLK_FREQ 假定 50 MHz [ASSUMED]（源码未约束，见 §10-2）。

判定口诀：**拿不出行号就不是事实；拿不出依据就不是推断；说不清影响就不要写死。**

## §2 时钟与复位识别

敏感列表判读表（权威规则，逐条对号入座）：

| 源码形态 | 结论 |
|---|---|
| `always @(posedge clk)` | 同步逻辑，clk 为该块时钟 |
| `always_ff @(posedge clk or negedge rst_n)` | 异步复位，低有效 |
| `always_ff @(posedge clk or posedge rst)` | 异步复位，高有效 |
| `always @(negedge clk_n)` | 下降沿时钟域 |
| `always_comb` / `always @(*)` | 组合逻辑 |
| `always_latch` | 锁存器意图 → latch 风险记入 §9 [UNVERIFIED] |

- **同步复位判定**：复位名不在敏感列表、但出现在块体首个 `if` 条件中。
- **CDC 检查**：≥2 个时钟域时，凡被两个域同时引用的信号必须在 §4.3 列出并识别同步手段：两级同步器 / 握手 / 异步 FIFO（格雷指针）/ 无保护（风险项）。
- **复位行为四问**（每个时序块必答）：极性？同步/异步？作用到哪些寄存器（**漏复位的寄存器要单独列出**）？复位释放后的初始态？

## §3 端口分组与职责归纳

步骤：
1. 从提取 JSON 取端口全集（这是覆盖率的分母）。
2. 对每个端口在源码中找全部驱动处或消费处。
3. 用一句动词开头的话写职责（载荷 + 方向 + 时机）。反例："数据信号"；正例："待发送字节，i_valid 为高的那一拍被采样"。
4. 按模板 §3.1 固定分组归类，位宽写公式。

命名模式速查（只能生成 [INFERENCE]，不能替代行号依据）：
`*valid/*ready` 流控；`*_addr/*_wdata/*_strb` 总线写通道；`*req/*ack` 握手；`*en/*we` 使能；`cfg_*/mode*` 配置；`dbg_*/probe_*` 调试；`*_n` 结尾常为低有效。

## §4 always 块归纳法

统一叙述模板（逐块套用）：
> 在 <时钟沿 / 组合求值>，当 <复位有效> 时 <复位动作>；否则当 <守卫条件> 时 <动作>；其余情况 <保持/默认>。

- case → 决策表：枚举全部分支 + default（default 缺失 → latch 风险，记入 §9）。
- if-else 链 → 明示优先级语义，给出优先级顺序。
- 计数/移位/拼接 → 写数学式：`cnt_next = (cnt == TOP) ? '0 : cnt + 1'b1;`
- 阻塞与非阻塞混用 → 记入 §9 综合注意。

## §5 状态机提取流程

1. **候选**：提取 JSON 的 `fsm_hints`；或信号名含 state/fsm/cs/ns。
2. **编码**：localparam 组或 typedef enum → 逐个抄录编码值（复现的硬契约）。
3. **转移**：读 case 块，条件一律符号化为信号级布尔式；**保持自环也要写进表**；禁止"等条件成熟"类自然语言。
4. **输出**：区分 Moore（输出仅依赖现态）/ Mealy（现态+输入）→ 输出函数表。
5. **必查项**：复位态、非法态处理（default 去向）、one-hot 冗余态、计数满回绕。

## §6 协议识别速查表

| 端口模式 | 协议 | 必须记录的时序要素 |
|---|---|---|
| aclk/tvalid/tready/tdata[/tlast/tkeep] | AXI-Stream | 握手规则（组合/寄存）、字节序、tlast 帧边界 |
| axi_{aw,w,b,ar,r} 前缀 | AXI4(-Lite) | 各通道独立握手、突发长度、ID/LEN 位宽 |
| psel/penable/paddr/pwdata/prdata | APB | setup→access 两相、penable 单拍 |
| sclk/mosi/miso/{cs_n,ss_n} | SPI | CPOL/CPHA、位序、帧长 |
| tx/rx + baud | UART | 帧格式（起始/校验/停止）、波特率公式 |
| scl/sda | I2C | 7/10bit 地址、速率模式 |
| 成对 valid/ready（无上述特征） | 自定义握手 | 采样时机、能否取消、满/空语义 |

识别不出标准协议时**不要硬套**：描述为"自定义接口"，照样写清握手语义与时序图。

## §7 位宽与参数公式规范

- 参数默认值逐字符照抄（`8'hFF` 不写成 `255`）。
- localparam 链逐条列公式 + 一个默认值算例。
- 拼接总宽 = 各段宽之和；比较/移位导致的隐式扩展 → 标 [UNVERIFIED] 提醒核对。

## §8 常见坑清单（发现即在报告相应章节记录）

1. 宏未展开：位宽到底是 `W` 还是 `8`？先索要 defines 文件；索要不到 → [ASSUMED]。
2. generate 展开：实例表要写"展开规则"，不能只列一处。
3. 隐式位宽截断/符号扩展。
4. latch：组合块缺 default/else。
5. 多驱动（tri-state、resolved net）。
6. 不吃复位的数据寄存器：上电为 X，功能上是否依赖初值？
7. 时序块中使用阻塞赋值。
